# QalaHub AI: публичная афиша Timepad

**Этап:** экспериментальный read-only поставщик событий для всех зарегистрированных городов Казахстана. Не создаёт отдельные приложения или базы для каждого города.

## Источник

Документация: https://dev.timepad.ru/api/get-v1-events/ . Публичный список событий `GET https://api.timepad.ru/v1/events.json`, фильтры `cities`, `starts_at_min`, `starts_at_max`, `fields=location`, `limit=50`. Публикация неполная: отображаются **только события, размещённые в Timepad**.

## Проверка сведений

- API `POST /api/discover/events`: JSON с `city`, `accessCode`. Доступ только по пилотному коду.
- Данные поставщика не считаются достоверными только из-за упоминания города в тексте: сервер сравнивает **location.city** с городским реестром и **location.country** с Казахстаном.
- Не показываем мероприятия без `starts_at` с часовым поясом, без адреса или корректного HTTPS URL события на Timepad.
- Прошедшие события, неопубликованные и события позже 21 дня исключаются; максимум 15 записей в чате.
- Время отображается в часовом поясе выбранного города (сейчас в реестре `Asia/Almaty`).
- Цены, продажи, наличие билетов, геокоординаты и подтверждение организатора **не заявляются**. Ссылка ведёт на страницу Timepad, где пользователь проверяет условия.
- Данные читаются без записи в Neon: нет массового импорта чужого каталога. Ответ кэшируется на сервере 30 минут.
- Если Timepad не возвращает событий по городу, интерфейс честно сообщает, что публикаций не найдено. Это **не** означает, что мероприятий в городе вообще нет.

## Ограничения и следующие этапы

API может быть ограничен по частоте и доступности. Автоматическая проверка TypeScript/тестов не подтверждает доступность Timepad с сервера Vercel. Для публичного запуска нужны лимиты, мониторинг и договорённости с организаторами/билетными платформами.

Следующий этап: проверка живой выдачи, интеграция партнёрских источников Казахстана (Ticketon/организаторы при наличии соглашения), устранение дублей и хранение подтверждённых событий в `city_event` с метками источника.

Контроль: тесты на Москва/Астана, Казахстан, даты, адреса, ссылки, приватные события, дубли, отсутствие публикаций и географические ограничения.
## Резервный веб-поиск (исправление 03.11.2026)

Если Timepad возвращает HTTP-ошибку, таймаут, некорректный ответ или пустую выдачу, кнопка автоматически вызывает существующий `/api/chat` с сохранением выбранного города, историей последних сообщений и обязательными ссылками на источники. Сервис показывает, что результаты получены из веб-поиска, а не из Timepad. При ошибочном коде доступа повторный платный запрос не выполняется. При очистке чата оба запроса прерываются. Ничего не записывается в базу без разрешённого источника. В серверных логах Timepad указывается безопасная категория сбоя (`upstream_http_403`, `upstream_invalid_json` и т.д.) без содержимого событий и ключей.

Timepad API официально заявляет, что чтение публичных событий не требует аутентификации, однако отдельные подключения могут возвращать ошибки доступа или ограничений. Серверный `TIMEPAD_TOKEN` поддерживается как необязательный параметр, но не требуется для резервного веб-поиска.
