# QalaHub AI: единая система для городов Казахстана

**Принцип:** один сайт, один ИИ-агент, одна API-система, единые модели и хранилище. Астана — первый город для проверки качества поиска, а не отдельный продукт.

## Общая структура

1. **Реестр городов:** стабильный `cityId`, названия на русском и казахском, синонимы, часовой пояс, режим покрытия.
2. **Каталог данных:** все события, места, организации, городские службы и исполнители ссылаются на `cityId`. События хранят время в ISO с часовым поясом; у записи есть URL первоисточника и время получения.
3. **Универсальные адаптеры:** `searchEvents(cityId)`, `searchPlaces(cityId)`, `getDetails(id)`. Один провайдер обслуживает все поддерживаемые им города.
4. **ИИ-агент:** получает выбранный город, язык, дату, бюджет, выбирает инструмент и проверяет источники. Никаких городских промптов, отдельных деплоев или разных интерфейсов.
5. **Контроль качества:** покрытие каждого города отмечается отдельно. Если местных данных мало, агент не выдумывает их и не переносит из других городов.

## Реализовано в первом универсальном шаге

- `apps/web/lib/cities.ts`: единый реестр из 22 предварительно выбираемых городов с машинными ID, альтернативными названиями и режимом покрытия. **Это не полный список городов и посёлков Казахстана.**
- `apps/web/lib/agent-request.ts`: город и часовой пояс для поиска берутся из реестра.
- `apps/web/lib/chat.ts` и `app/page.tsx`: единая проверка города, приведение названия к каноническому и честная отметка экспериментального покрытия.
- `apps/web/lib/location-guard.ts`: данные о городах Казахстана для фильтрации берутся из общего реестра, а не поддерживаются двумя независимыми списками.
- `apps/web/lib/city-data.ts`: универсальные интерфейсы событий, мест и происхождения информации, фильтрация записей строго по `cityId` и дате. **Это код моделей, реальная база данных и внешние API пока не подключены.**

## Следующие задачи

1. Подключить полный юридически разрешённый реестр населённых пунктов и административных единиц Казахстана, включая совпадающие названия в разных регионах. Стабильные идентификаторы должны исключать путаницу.
2. Разместить реестр и нормализованные сущности в PostgreSQL; UI получает список городов через API, без релиза для каждого населённого пункта.
3. Подключить источники афиши, мест, адресов и времени работы с соответствующими лицензиями. Создать фоновые обновления и устранение дублей.
4. Сделать структурированную проверку города/адреса/даты/провайдера до генерации ответа.
5. Масштабировать покрытие на другие города только после измерения качества. Голосовые помощники работают с тем же ядром через адаптеры.

## Что **не** следует делать

- Не создавать отдельные репозитории, версии ИИ или базы на каждый город.
- Не считать, что запись «найдена в сети» означает подтверждённый адрес, цену или действующую афишу.
- Не добавлять выдуманные заведения и события в seed-данные.
- Не объявлять 22 предварительно выбираемых города полным покрытием Казахстана.
- Не делать прямую зависимость от «Мир Услуг 2», старого QalaHub или Notify KZ: подключение через интерфейсы интеграций.

**Целевая модель:** новые города добавляются **данными, а не новым кодом приложения**. Сейчас для этого создана программная основа; полноценное подключение через БД и провайдеров — следующий этап.
