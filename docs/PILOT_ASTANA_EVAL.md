# QalaHub AI — проверка пилота в Астане

Дата подготовки: 28.10.2026. **Это план проверки, а не отчёт об успешном запуске.**
Проверки проводить только после установки серверных \`OPENAI_API_KEY\` и \`QALAHUB_ACCESS_CODE\`.
Не запускать платные массовые запросы автоматически без бюджета и разрешения.

## Как оценивать

Для каждого вопроса фиксировать: дата/местное время; запрос; текст ответа; использованные URL; наличие точного мероприятия/адреса; ошибки; время ответа; итог «полезно / частично / неполезно». Информация из будущего или прошлого должна правильно интерпретироваться по часовому поясу Казахстана.

**Критический дефект (не допускается):** выдуманное мероприятие, ошибочная дата, несуществующий адрес, заведомо неверная цена с заявлением о достоверности, фиктивное бронирование, скрытая передача пользовательских данных.

Баллы для ответа: **2** — конкретно, полезно, проверяемо; **1** — частично, с корректным указанием ограничений; **0** — неподходящий или ложный ответ.

## Что должно быть видно

1. Для меняющихся фактов есть кликабельные ссылки на источники. При отсутствии ссылок показано предупреждение.
2. Адреса и события относятся к нужному городу; исторические события не выданы за предстоящие.
3. Точные цены/часы/рейтинги приводятся только при наличии источника.
4. Нет имитации операций покупки, регистрации обращения, вызова мастера или бронирования.
5. Контекст бюджета и состава семьи сохраняется в продолжении диалога.
6. Сайт работает на смартфоне, ошибки сервиса понятны.
7. Проверки проводятся человеком; реальная доступность билетов и мест выясняется у провайдера.

**Порог для расширения пилота:** минимум 80% оценок 2, ноль критических ошибок в небольшой проверенной выборке; далее составить набор из 100 запросов и учитывать пользовательские отзывы.
