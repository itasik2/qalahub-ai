# Передача проекта QalaHub AI в следующий чат

**Основной документ:** docs/TZ_QALAHUB_AI_2026-10-28.md  
**Репозиторий:** https://github.com/itasik2/qalahub-ai  
**Пилот:** Астана; общая география — весь Казахстан.

## Коротко о концепции

QalaHub AI — самостоятельный городской ИИ-агент: поиск реальных событий, заведений и досуга, планирование выходных и маршрутов, помощь с бытовыми проблемами, позднее — заявки, бронирования и голосовые помощники. Он должен выдавать проверяемые и актуальные сведения с первоисточниками, учитывать город, дату и бюджет и не совершать действия без подтверждения.

НЕ путать с исходным QalaHub (автоматическая диспетчеризация мастеров). НЕ объединять с miruslug-2. Интегрировать miruslug-2 и notify-kz в будущем как отдельные сервисы.

## Фактически готово к 28.10.2026

- Репозиторий создан, ветка main содержит Next.js 15 / React 19 MVP.
- Страница с чатом, выбором города, готовыми сценариями.
- POST /api/chat вызывает OpenAI Responses API + web_search с серверным ключом.
- Есть URL-источники, валидация и базовые тесты; GitHub Actions прошёл.
- PR #1 объединён в main.

## Не готово

- Подтверждённый Vercel deployment и работа с действующим API-ключом.
- Структурированные источники событий/мест, 2ГИС/Ticketon API, карты.
- PostgreSQL и worker для городских данных.
- Регистрация, лимиты/бюджеты для публичного использования.
- Интеграции «Мир Услуг 2», Notify KZ, Telegram и Алиса.

## Следующее действие

Проверить текущее состояние GitHub/CI/деплоя, затем развернуть apps/web на Vercel, настроить OPENAI_API_KEY и QALAHUB_ACCESS_CODE только в серверной среде и провести реальные тесты по Астане. После этого — структурированные инструменты поиска и контроль качества.

Владелец должен открыть одноразовую ссылку \`authorize_team_access\` и разрешить доступ, после чего повторить создание проекта с Git \`itasik2/qalahub-ai\`, \`rootDirectory=apps/web\`, Next.js и защитой закрытого пилота. Ссылка согласия временная; при возобновлении работы запрашивать новую при необходимости.
- Секреты \`OPENAI_API_KEY\` и \`QALAHUB_ACCESS_CODE\` не настроены в Vercel и не должны храниться в репозитории.
- Следующая задача: авторизовать Vercel, создать/проверить проект и первую сборку, безопасно настроить секреты через интерфейс Vercel, проверить \`/api/health\`, затем провести ручные запросы из \`docs/PILOT_ASTANA_EVAL.md\`.

Важно: успешный CI не означает, что реальный OpenAI API и информация по Астане уже проверены. Не утверждать этого в следующем чате.
